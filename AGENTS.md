# go-writer-ai

Unofficial Go client for the Writer (writer.com) API, generated with oapi-codegen. If you only want to use the client from an agent, read [.agents/skills/go-writer-ai/SKILL.md](.agents/skills/go-writer-ai/SKILL.md) instead; this file is about changing the code.

## Architecture

`make generate` runs `go generate ./...`, which runs the steps in `gen.go`:

1. `scripts/fetch-spec.sh` reads `openapi_spec_url` from the `.stats.yml` of writer/writer-python and downloads that spec to `api/openapi.yaml`.
2. oapi-codegen (`go tool oapi-codegen`) reads `config.yaml` and writes `client.gen.go`.

The spec needs no patch step. If a future spec breaks oapi-codegen, add a patch step to `gen.go` that writes a fixed copy under `api/`.

## Stack

- Go 1.26.9, one package `writer` at the module root.
- oapi-codegen v2 and golangci-lint as `go tool` dependencies.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`: package doc and the `go:generate` steps.
- `config.yaml`: oapi-codegen config (`number` to `float64`).
- `client.gen.go`: generated, committed.
- `client_test.go`, `example_test.go`: tests against `httptest` and the README example.
- `scripts/`: spec fetch, lint and security scan scripts the Makefile runs.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate client.gen.go
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The Stainless spec URL carries a content hash and changes on every upstream update. Never hardcode it; `fetch-spec.sh` looks it up each run.
- Several operations have no `operationId`, so their methods are named from the method and path (`GetV1Applications`, `PostV1ToolsWebSearch`). Upstream adding an ID renames the method.
- The spec types some IDs as UUIDs and others as plain strings, so `graphId` and `applicationId` parameters differ in Go type between methods.
- Regenerating can rename types when upstream schemas change (the `...Response2` names come from collision resolution). Check the tests and the skill after every `make generate`.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
